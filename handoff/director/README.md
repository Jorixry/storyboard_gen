# 导演分镜知识采集包 - 填写说明

这套文件用于把导演的专业判断整理成开发者可以映射到3D场景和结构化Prompt的数据。它不是让你编写代码，也不是让你直接写最终Prompt。

## 请提交哪些文件

把整个 `handoff/director/` 文件夹复制给项目发起人。项目发起人填写后，至少交回：

```text
director-handoff-return/
├─ shot-template-intake.csv
└─ reference-images/
   ├─ dialogue_medium_two_shot.webp
   ├─ dialogue_ots_a_to_b.webp
   └─ dialogue_ots_b_to_a.webp
```

可直接使用本目录中的：

- `shot-template-intake.blank.csv`：空白采集表，复制后重命名为 `shot-template-intake.csv`；
- `shot-template-intake.example.csv`：填写示例，仅用于理解格式，参数不是导演定稿；
- `reference-images/README.md`：参考图片命名、来源和授权要求。

第一轮只需填写3个模板，不要一开始填写全部8-12个：

1. 双人中景；
2. 角色A过肩拍角色B；
3. 角色B过肩拍角色A。

这三个模板审核通过后，再批量扩展。

## 谁填写什么

### 项目发起人/导演负责

- 镜头的专业名称和普通用户看得懂的解释；
- 叙事目的、情绪效果、适用与不适用情况；
- 构图、站位、视线、轴线和运镜要求；
- 合格画面应该满足的可观察标准；
- 参考图及其来源/授权说明；
- 有把握的景别、焦距或摄影术语；
- 不确定、需要一起验证的事项。

### 开发者负责

- 把自然语言映射成3D坐标、旋转角度和相机目标；
- 把采集结果转成YAML/JSON；
- 校验Schema、ID和字段格式；
- 在通用房间和通用人偶中制作可交互预览；
- 根据导演反馈修正结构化参数；
- 将结构化语义编译成不同模型的Prompt。

导演不需要填写3D坐标，不需要编辑YAML，不需要编写Codex Skill。

## CSV填写规则

### 文件格式

- 使用UTF-8编码的CSV文件。
- 第一行字段名不得修改、翻译、删除或重新排序。
- 一行只描述一个分镜模板，不描述整场戏或完整镜头序列。
- 不要合并单元格，不要添加工作表，不要在表格上方插入标题。
- 多个值使用半角竖线 `|` 分隔，例如：`紧张|压迫|对峙`。
- 如果内容包含英文逗号、换行或双引号，保存时必须保留标准CSV引号；不确定时避免在单元格中换行。
- 不确定的内容填写 `待确认`，不要为了填满表格而猜测。

### ID格式

- `template_id` 必须使用小写英文字母、数字和下划线。
- 示例：`dialogue_ots_a_to_b`。
- ID必须唯一；一旦进入开发，不要随意改名。
- 左右角色统一用 `A`、`B` 表示，不使用演员姓名。

### 单位和术语

- 焦距使用毫米，例如 `35`、`50`、`85`；不知道可以填 `待确认`。
- 运镜时间使用秒，但导演采集表中可先用自然语言描述，例如“4秒缓慢推近”。
- 专业术语可以填写，但 `plain_description_zh` 必须让非科班创作者也能理解。
- `prompt_semantics_zh` 填写必须表达的画面事实，不要粘贴一整段厂商Prompt。

### 参考图

- `reference_image_filename` 必须与提交文件名完全一致，包括扩展名。
- 推荐WebP或PNG，画面清晰且不带无关UI截图。
- 每个模板至少一张主参考图。
- 备用图命名为 `<template_id>__alt_01.webp`、`__alt_02.webp`。
- 必须填写 `reference_rights_note`：原创、自摄、已购授权、明确许可证，或“来源未知，仅供内部研究”。
- 来源未知的图片不能进入对外MVP，只能用于内部讨论。

## 必填字段

下列字段第一轮不得留空：

- `template_id`
- `display_name_zh`
- `plain_description_zh`
- `narrative_purpose_zh`
- `when_to_use_zh`
- `reference_image_filename`
- `reference_rights_note`
- `shot_size_zh`
- `camera_view_description_zh`
- `character_a_blocking_zh`
- `character_b_blocking_zh`
- `movement_description_zh`
- `continuity_rules_zh`
- `acceptance_checks_zh`

`focal_length_mm_optional` 可以填 `待确认`。Prompt语义可以先写中文短语。

## 什么叫合格的填写结果

每个模板应让开发者不依赖猜测就能回答：

1. 用户为什么选择这个镜头？
2. 画面中谁是视觉重点？
3. 相机大致位于人物哪一侧、什么高度和角度？
4. A和B分别站在哪里、朝向哪里？
5. 相机是否移动，如何移动？
6. 哪些轴线、视线或构图条件不可破坏？
7. 看一张3D预览图时，怎样判断“合格/不合格”？
8. 参考图是否允许进入产品？

如果只能回答“看起来更电影感”，信息仍然不够。应写成可观察要求，例如“角色B双眼保持在画面上三分之一附近”“角色A肩部只占左侧少量前景”。

## 审核流程

### 第一次：完整性审核

开发者只检查：字段是否完整、文件名是否匹配、格式是否可转换、是否超出MVP能力。开发者不替导演判断专业内容是否正确。

### 第二次：3D映射审核

开发者把采集内容映射到通用房间、两个人偶和相机，交付：

- 导演视角截图；
- 相机视角截图；
- 运镜起点和终点截图；
- 结构化参数摘要；
- 未能映射的内容清单。

导演逐项指出“通过”“修改”或“该要求无法用当前MVP表达”。

### 第三次：模板批准

只有同时满足以下条件才可批准：

- 参考图来源可接受；
- 3D预览符合导演意图；
- 普通用户标签容易理解；
- 合格标准可以观察；
- 所有规则可由当前MVP表达；
- 导演以文字确认模板ID和版本。

在导演明确确认之前，开发者只能将模板标记为 `engineering_ready` 或 `director_review`，不能标记为 `approved`。

## 内容约束

- 当前只采集两人对话场景。
- 当前只使用一个通用房间、两个通用人偶和一个相机。
- 不要求角色换装、面部、骨骼姿势或自定义3D模型。
- 运镜只有一个起点和一个终点，不设计多关键帧时间线。
- 不把视频生成、剪辑、节点工作流写入分镜模板。
- 不为了某一个模型把导演知识写死成最终Prompt。

如果一个模板无法在这些约束内表达，记录在 `director_notes_zh`，不要偷偷扩展MVP。
